# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/). Public contracts: the model schema
`schema_version`, the `dist/` TextMate scope names, the engine JSON format
`engine_format`, and the TypeScript engine API (`loadEngine`, `Interpreter`, `accepts`
and the `Verdict` type).

## [Unreleased]

### Added
- `npm run bench -w packages/engine`: load, first and second verdict per diagram family
  in fresh processes, with `--patterns` for the costliest regexes.

## [1.0.0] - 2026-10-26

### Added
- The PlantUML command model (`model/`, `schema_version` 1): models generated from the
  upstream sources at `97a5992` (`1.2026.8beta1`) by the Java extractor and the translator,
  refined by hand per diagram family, each rule citing its upstream `file:line`.
- The interpreter (`tools/interp`): ordered first-match command matching over a context
  stack, with Java regex semantics (`tools/model/java_regex.py`), as PlantUML runs its
  command factories.
- The TextMate grammar `dist/plantuml.tmLanguage.json` (`source.plantuml`), generated from
  the model and proved with `vscode-textmate`.
- The parity harness (`tools/validate`): every `@start...@end` block of the vega,
  plantuml-ts and pdiff corpora through the PlantUML jar and the interpreter, with every
  false accept or reject classified (`reports/classify/`).
- The TypeScript engine (`packages/engine`): a port of the interpreter with a browser-safe
  core (ES2022, no Node APIs) and the public API `loadEngine`, `Interpreter` and
  `accepts`. Its verdicts equal the Python interpreter's in `accepted`, `diagram`,
  `model`, `status` and `first_failure` on all 3,672 conformance goldens
  (`tests/conformance`, recorded by `tools.validate.conformance`) and on every block of
  the three corpora (0 mismatches).
- `dist/plantuml.engine.json` (`engine_format` 1): the resolved model with every regex
  translated to ES2018 JavaScript (flag `u`), prefix-closure regexes for multi-line joins,
  and native recognizers for the two recursive JSON leaves; generated by
  `tools.emit.build`.
- A JSONL CLI for the engine with a killable worker pool
  (`node packages/engine/dist/cli.js --engine <path>`), and `--engine py|ts|both` in the
  parity harness, with TS reports (`reports/parity-*-ts.*`) and a Python/TS equality
  report (`reports/engine-equality-*`).
- The npm package `@knowvah/plantuml-grammar` (the `packages/engine` workspace): the
  TextMate grammar, the engine model and the engine's browser-safe core, published by
  semantic-release with npm trusted publishing and mirrored to GitHub Packages
  ([PUBLISHING.md](PUBLISHING.md)).

### Changed
- The nwdiag packet field regexes (`PK_ZERO_FIELD`, `PK_NONZERO_FIELD`) are rewritten
  without regex conditionals, which JavaScript lacks, as an exact enumeration over the
  bounded field digits. Interpreter verdicts and parity are unchanged.
