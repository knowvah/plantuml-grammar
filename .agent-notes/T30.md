## Observation: chart data parsing follows Java String.split quirks
- **Context**: modelling `bar [...]`, `line [(x,y),...]`, `v-axis ticks [...]`.
- **Finding**: `split(",")` drops trailing empty strings, so `[1,2,]`, `[,]` and `[),(]` (zero pairs) are accepted while `[,1]`, `[ , ]` and `[1,,2]` fail. Coordinate data has all ASCII whitespace removed first, so `(1 .5,2)` is the pair (1.5, 2). `v-axis [labels]` returns before range/ticks/spacing are parsed, so `v-axis [a] spacing 0` is accepted. Double.parseDouble accepts hex floats, NaN/Infinity (case-sensitive) and f/d suffixes. All oracle-verified.
- **Confidence**: High
